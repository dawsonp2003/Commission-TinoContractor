# Project Intake Template

Copy this file once per project. Aim for **8–12 for launch**. A voice memo covering these points is
just as good as filling in the blanks.

Fields map directly to the `Project` schema in
[`../docs/09-sitemap-and-content-model.md`](../docs/09-sitemap-and-content-model.md), so a filled-in
copy can be turned into a live page without a second conversation.

## The story

The most valuable and most-skipped part. If only one section gets filled in, make it this one.

- **What was the situation before?**
- **What did the client want?**
- **What was the hard part?** Something unexpected, a bad existing condition, a tight space, a code
  issue, something a less careful contractor would have gotten wrong.

- **What was the outcome?**

## Photos — permission gates

**Fill these in before any photo goes on the site.** These map to the schema fields that block
publishing, so a wrong answer here is caught by the build rather than by a lawyer.

| Question | Answer |
| --- | --- |
| Who took the photos? | |
| Whose property is it? | own / client / employer jobsite |
| `ownProperty` | true / false |
| Was this done for a previous employer? (`priorEmployerWork`) | true / false |
| Signed release on file? (`releaseOnFile`) | true / false / n/a |
| Any NDA or confidentiality agreement covering this job? | |
| **Safe to publish photos?** | **yes / no — prose only** |

If photos aren't publishable, that's fine — **the project is still worth a written entry.** This is
how the municipal pipe-network experience gets represented, and prose is what a municipal buyer
searches with anyway.
